## Что это

Bounty Pilot задаёт coding-агенту последовательный процесс: разобраться в проекте, определить scope, исследовать потенциальные ошибки, проверить их тестами и подготовить репорт.

**Это навык для агента с инструментами, а не отдельный онлайн-сканер.** Основной профиль — Solidity/EVM; для Rust/Solana предусмотрен более узкий маршрут. Python-скрипт помогает организовать результаты и проверить их структуру. Сам он уязвимости не ищет и не доказывает.

## Запуск за минуту

**1. Отправь агенту команду**, заменив `OWNER/TARGET` на нужный проект:

```text
Install https://github.com/dimin4241-svg/bounty-pilot
and run Bounty Pilot on https://github.com/OWNER/TARGET.
Read skills/bounty-pilot/SKILL.md and follow it.
Keep findings private. Explain results in Russian.
```

**2. После установки для следующего проекта достаточно:**

```text
Bounty Pilot: https://github.com/OWNER/TARGET
```

Можно приложить ссылку на bounty-программу. Без неё анализ исходников начнётся, но пригодность находки для подачи и выплаты останется неподтверждённой.

## Что он делает

| Этап | Результат |
| --- | --- |
| Проверяет исходные данные | Фиксирует commit, scope, правила программы и неизвестные параметры deployment |
| Строит модель | Описывает активы, роли, переходы состояний и свойства, которые должны сохраняться |
| Проводит до трёх разных проходов | Проверяет доступы и изменения, учёт средств, интеграции и пропущенные пути |
| Воспроизводит кандидатов | Создаёт локальный PoC, сохраняет результат и контрольный сценарий |
| Перепроверяет выводы | Разделяет техническую валидность, severity, scope и известные проблемы |
| Готовит результат | Пишет понятное резюме и английский черновик репорта |

Если среда позволяет, независимые задачи могут выполняться параллельно — до четырёх исполнителей по умолчанию. Иначе работа идёт последовательно. Бесконечного цикла и обязательной нормы находок нет.

### Статусы находок

| Статус | Значение |
| --- | --- |
| `hypothesis` | Есть механизм, который стоит проверить |
| `needs-evidence` | Не хватает конкретного эксперимента или факта |
| `verified` | Выполнены требования процесса к техническим доказательствам; scope оценивается отдельно |
| `refuted` | Есть конкретное опровержение из кода, спецификации или теста |

Отсутствие инструментов не означает «баг невалиден». Предположение «наверное, так задумано» тоже недостаточно для отклонения. При этом согласие нескольких моделей не заменяет работающий тест.

## Что потребуется

- Coding-агент с доступом к файлам, Git и запуску тестов.
- Python 3.9+ и Git для вспомогательного скрипта; внешние Python-библиотеки не нужны.
- Инструменты проверяемого проекта: например Foundry, Cargo или локальный Solana test harness.
- Доступ к публичным источникам для проверки правил программы и известных проблем.

Обычный чат без инструментов не сможет выполнить все этапы. Использование модели оплачивается по условиям твоего сервиса. По умолчанию объяснения на русском, черновики репортов — на английском.

## Внешние skills

Набор работает самостоятельно. При необходимости агент может использовать отдельные модули:

| Проект | Для чего |
| --- | --- |
| [Pashov](https://github.com/pashov/skills) | Подготовка, поиск Solidity-кандидатов и fuzz-тесты |
| [Trail of Bits](https://github.com/trailofbits/skills) | Изменения кода, варианты багов, ложные срабатывания и тестирование свойств |
| [0xSimao](https://github.com/0xsimao/0xsimao-ai) | Независимая проверка учёта средств |
| [QuillShield](https://github.com/quillai-network/quillshield_skills) | Пропущенные проверки и инварианты |
| [Sanbir](https://github.com/sanbir/solidity-auditor-skills) | Дополнительные EVM-проверки, частично пересекающиеся с Pashov |

**Эти проекты не встроены и автоматически не скачиваются.** Перед подключением нужно проверить инструкции, лицензию и зафиксировать версию. Подробности — в [правилах интеграции](skills/bounty-pilot/references/integrations.md). Это самостоятельный процесс, а не переименованная копия чужих skills.

## Где что лежит

| Файл | Назначение |
| --- | --- |
| [SKILL.md](skills/bounty-pilot/SKILL.md) | Главная инструкция агенту |
| [lenses.md](skills/bounty-pilot/references/lenses.md) | Направления поиска по стеку |
| [evidence.md](skills/bounty-pilot/references/evidence.md) | Требования к доказательствам |
| [report.md](skills/bounty-pilot/references/report.md) | Шаблон английского репорта |
| [bounty.py](skills/bounty-pilot/scripts/bounty.py) | Создание каталога аудита и проверка записей |
| [test_bounty.py](tests/test_bounty.py) | Тесты вспомогательного скрипта |

```sh
# Новый приватный каталог вне проекта и папки навыка.
python3 skills/bounty-pilot/scripts/bounty.py init \
  --repo /path/to/target --out /path/to/private/new-run

# Проверка структуры записей и наличия файлов доказательств.
python3 skills/bounty-pilot/scripts/bounty.py check \
  --run /path/to/private/new-run

# Тесты самого вспомогательного скрипта.
python3 -m unittest discover -s tests -v
```

`init` не скачивает проект и не запускает его код. `check` не проверяет истинность уязвимости, корректность severity или право на выплату. Пустой список находок также может пройти структурную проверку.

## Частые вопросы

**Будет находить больше оплачиваемых багов?**  
Пока это не измерено. Сравнительного benchmark и гарантии выплат нет. Цель — сделать исследование и доказательства более последовательными.

**Сможет исключить дубликаты?**  
Можно сравнить находку с публичными аудитами, issues и исправлениями. Закрытые репорты других исследователей недоступны.

**Опубликует или отправит репорт сам?**  
Нет. Результаты остаются приватными. Отправка и раскрытие требуют отдельного указания пользователя.

**Можно ли улучшить набор?**  
Да. Полезны дополнительные проверки для конкретных экосистем, исправления со воспроизводимыми примерами и синтетические тесты. Опиши изменение и способ проверки в issue или pull request. Не публикуй чужие закрытые исходники, секреты и нераскрытые уязвимости; см. [SECURITY.md](SECURITY.md).

## Ответственное использование и лицензия

Исследуй только разрешённые цели и соблюдай правила программы. Проверяй PoC локально, без секретов и отправки атакующих транзакций в рабочую сеть. Полнота аудита, оригинальность находок и принятие репортов не гарантируются.
